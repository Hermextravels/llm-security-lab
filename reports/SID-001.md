
# SID-001: Missing Document-Level Authorization

## Summary
The document retrieval function allows an authenticated
user to access another user's confidential document.

## Affected Component
app/documents.py
Function: get_document_vulnerable()

## Vulnerability
CWE-862: Missing Authorization

## Preconditions
- Alice is an authenticated user.
- Bob owns document doc-002.
- Alice knows or can supply doc-002's identifier.
- The application invokes the vulnerable function.

## Source-to-Sink Trace
1. Alice supplies document_id = "doc-002".
2. The application retrieves the document.
3. No document ownership check is performed.
4. Bob's confidential content is returned to Alice.

## Root Cause
The function accepts user_id but does not enforce
authorization against the document owner.

## Impact
Unauthorized disclosure of confidential user data.

## Remediation
Verify the requesting user's authorization before
returning document content.

## Validation
pytest confirms:
- Vulnerable implementation discloses Bob's data.
- Fixed implementation blocks Alice.
- Authorized access for Bob remains functional.
- Hard-negative implementation enforces access control.

## Static Analysis
Bandit 1.9.4 reported zero findings.

This is a known false negative for this test case,
not evidence that the vulnerable code is secure.

## Residual Risk
The demonstration assumes the user identity is trusted.
Production systems must derive identity from verified
authentication context and enforce tenant-level access.
